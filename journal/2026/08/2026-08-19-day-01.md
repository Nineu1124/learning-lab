## 学习者原始总结

> 1、API是软件之间约定的通信接口，API Key是一串字符形式的身份凭证，用来认证或者授权api请求。
>
> 2、model是大模型，toolcalling是工具请求、agent loop是一个turn内部的循环，agent loop可以调用大模型、调用工具、然后看工具返回结果、再调用大模型。
>
> 3、harness是马甲的意思，相当于包含了agent loop和agent runtime的一个综合agent工具，可以接对应的大模型大脑来执行一系列操作。而agent runtime是管理session、turn、event以及生命周期的。
>
> 4、tsukiori我觉得处在快到harness那一层，这是我最开始想设置这个软件的目的，做一个能调用其他harness的harness。
>
> 5、agent runtime是管理session、turn、event以及生命周期的，并不是运行时的环境和状态
>
> 6、仍然不知道tsukiori目前是怎么运行的，codex、claudecode是如何调用自家大模型运作的

## 导师事实纠正

1. Tool Calling 不只是“工具请求”，而是 Model 与外部执行程序之间表达工具名称、参数和结果的协议。
2. Harness 通常封装 Agent Loop、工具、上下文、权限和工作方式，但不应默认认为它一定包含课程中定义的完整 Agent Runtime。
3. Tsukiori 当前更准确地定位为 `Host / Control Plane + Runtime integration`：通过 Adapter 管理外部 Harness。未来增加 Native Agent Loop 后，它会多出内置 Harness-like execution path。
4. “调用其他 Harness 的 Harness”容易混淆层级；应描述为“管理多个 Harness 的 Host”。

## 修正过的错误理解

- API 不是 API Key；API Key 是字符串形式的身份凭证。
- Tool Calling 关注通信协议，Agent Loop 关注控制流程。
- Agent Runtime 不是单纯的操作系统、进程和资源环境。
- 代码存在、产品计划和端到端稳定性属于不同证据状态。
