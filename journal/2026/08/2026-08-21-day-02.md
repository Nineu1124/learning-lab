## 诊断问题与回答

- 通过 `role: "user" | "assistant"` 理解 string literal union 只允许列出的值。
- 通过 `createdAt?: number` 理解 optional property，知道删除 `?` 会使字段必填。
- 通过 `AgentEvent` 理解需要先检查 `event.type`，再读取对应 variant 的字段。
- 通过 `Record<string, unknown>` 理解 `unknown` 必须先验证再使用，而 `any` 会跳过检查。
- 通过 `Session` 理解 class 是模板，`a` 是 instance，`a.start()` 会改变状态。
- 通过两个模块理解 export、import、`./tool` 和 `../tool`。

## 核心概念

1. `interface` 描述对象在 compile time 应具有的结构。
2. discriminated union 使用公共判别字段缩小类型范围。
3. function 的结果由执行到的 `return` 决定，判别字段本身不会自动成为输出。
4. class 定义属性和行为，instance 是由 class 创建的具体对象。
5. TypeScript 类型会从编译后的 JavaScript 中擦除。

## 失败、边界或反例

临时加入 `createdAt: "今天"` 后，编译器真实输出：

```text
main.ts(28,3): error TS2322: Type 'string' is not assignable to type 'number'.
```

删除该字段后重新 typecheck 通过。另一个边界是 `interface` 和 `type` 不存在于 JavaScript runtime，因此不能把 `Message` 当成运行时变量输出。

## 验收问题与回答

- `interface` 描述对象应有的属性和方法。
- `AgentEvent` 通过公共字段 `type` 形成 discriminated union，检查它后可以缩小类型范围。
- TypeScript 类型只在编译阶段存在，编译后会被删除。
- class 是模板，instance 是根据 class 创建的具体对象。
- `event.type` 提供事件类型信息，函数最终结果来自执行分支的 `return`。

## 我自己的总结

> `interface` 是 TypeScript 用来定义对象结构的工具，它规定一个对象应该有哪些属性和方法，帮助开发者在编写代码时获得类型检查和提示。
>
> `AgentEvent` 可以根据 `type` 判断字段，是因为 TypeScript 支持**判别联合类型（Discriminated Union）**，通过公共字段 `type` 的不同值缩小类型范围，从而知道当前事件允许访问哪些字段。
>
> TypeScript 的类型信息只存在于编译阶段，代码转换成 JavaScript 后类型会被删除，运行时并不能直接看到 `interface` 或类型定义。
>
> `class` 是创建对象的模板，定义对象拥有的属性和方法；`instance` 是根据这个 class 创建出来的具体对象，一个 class 可以产生多个不同的 instance。
>
> event.type只是提供事件类型信息，函数最终的结果是return返回的字符串
